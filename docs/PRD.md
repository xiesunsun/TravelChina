|   |   |
|---|---|
|文档版本|V2.0 (基于已实现原型迭代)|
|产品名称|**绘行中华 (Huixing Zhonghua)**|
|核心理念|**以地为纸，以足为墨，共绘青绿山水**|
|涉及角色|全栈/前端工程师、AI交互设计师|

## 1. 产品概述

### 1.1 产品定位

一款融合了**新中式美学**与**AI情感化交互**的个人旅行记录工具。它不仅仅是记录足迹，更是通过用户的探索，逐渐点亮一幅“青绿山水”风格的中国电子画卷。

### 1.2 核心体验

- **视觉**：摒弃传统地图的科技感，采用**青绿山水（石青、石绿）**的晕染风格，配合**朱砂印章**。
    
- **交互**：引入**AI伴侣“伴”**，通过温婉知性的对话引导用户记录回忆，而非填鸭式表单。
    
- **呈现**：以**“舆图”**（地图）和**“画卷”**（长轴列表）两种形态展示人生足迹。

## 2. 功能模块详细说明

### 2.1 卷首·舆图 (Interactive Ink Map)

- **布局**：
    
    - **右上角**：胶囊式导航栏（舆图 | 画卷），避开地图主体。
        
    - **右下角**：**题跋式统计框**。竖排布局，双线边框，展示“已阅 X 处山河”及图例。
        
    - **左上角**：产品Logo“绘”，配合英文注脚。
        
- **地图渲染 (ECharts)**：
    
    - **底图**：极淡的白描线条（未去过的地方）。
        
    - **足迹（面）**：用户记录过的省份，应用**线性渐变（石青 -> 石绿）**，并带有水墨晕染的阴影扩散效果（ShadowBlur）。
        
    - **印记（点）**：具体的城市坐标显示为红色**方印**，带有缓慢的呼吸水波纹动效。
        
- **交互逻辑**：
    
    - 点击省份/区域 -> 触发记录模态框。
        
    - 判断逻辑：
        
        - **初次涉足**：进入 **AI向导模式**。
            
        - **重游故地**：进入 **极简表单模式**。
            

### 2.2 执笔·记录 (Smart Recording)

- **AI向导模式 (Wizard Mode)**：
    
    - **角色**：虚拟伴侣“伴”（红色方印头像）。
        
    - **风格**：温婉、知性、现代诗意。
        
    - **流程**：
        
        1. AI 根据点击的省份发起提问（调用 Gemini API 或 兜底文案）。
            
        2. **思考动效**：AI 思考时，输入框**严格隐藏**，避免剧透。
            
        3. **用户回答**：分步引导（地点 -> 日期 -> 天气 -> 照片 -> 随笔）。
            
        4. **预览盖印**：展示仿古卡片预览，用户确认后入库。
            
- **极简表单模式 (Form Mode)**：
    
    - 单页展示所有字段，方便快速修改或补录。
        

### 2.3 阅卷·画卷 (Scroll View)

- **布局**：横向滚动长轴，模拟《千里江山图》的观看方式。
    
- **卡片设计**：
    
    - 左图右文（或上图下文）。
        
    - 图片应用 sepia (泛黄) + contrast 滤镜，融入古风。
        
    - **印章装饰**：卡片右上角根据城市名自动生成对应的“XX印”装饰。
        
- **功能**：点击卡片上的“分享”按钮，生成图片。
    

### 2.4 赠言·锦书 (Share)

- **技术**：基于 html2canvas。
    
- **样式**：生成一张带有宣纸纹理、双线边框、竖排文字的图片，包含照片、描述、日期及印章，供用户保存分享。

## 3. 技术栈架构 (Tech Stack)

### 3.1 前端 (Current)

- **核心框架**: React 18+ / TypeScript
    
- **构建工具**: Vite
    
- **UI 样式**: Tailwind CSS (配置自定义颜色变量：cinnabar, ink, mineralGreen 等)
    
- **地图引擎**: Apache ECharts 5 (配合 Aliyun GeoJSON)
    
- **AI 集成**: Google GenAI SDK (Gemini 2.5 Flash)
    
- **图标库**: Lucide React
    
- **工具库**: html2canvas (截图), date-fns (日期处理)
    

### 3.2 后端 (Current + Next)

当前版本已使用后端 API 作为主数据链路，不再依赖 localStorage 作为主存储：

- **Runtime**: Python 3.12+
- **Framework**: FastAPI
- **Database**: SQLite（当前），后续可迁移 MySQL
- **ORM**: SQLAlchemy 2.x + Alembic
- **Auth**: JWT Bearer
- **Object Storage**: 阿里云 OSS（通过后端上传接口）

后续演进方向：

- 引入多端统一登录（微信/手机号）
- 从 SQLite 平滑迁移到 MySQL
- 增加更细粒度的权限与审计

## 4. 前后端对接技术文档 (API Design)

当前生效接口统一使用 `/api/v1` 前缀。

### 4.1 鉴权接口

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`

登录后返回 JWT，后续请求携带：

`Authorization: Bearer <token>`

### 4.2 足迹接口

- `GET /api/v1/records/`
- `POST /api/v1/records/`
- `PUT /api/v1/records/{record_id}`
- `DELETE /api/v1/records/{record_id}`

### 4.3 AI 接口

- `POST /api/v1/ai/chat`
- `POST /api/v1/ai/resolve_location`

### 4.4 上传接口

- `POST /api/v1/upload/`（`multipart/form-data`）

## 5. 后续开发建议 (Future Roadmap)

### Phase 1: 体验打磨 (Immediate)

1. **移动端适配优化**：ECharts 在手机端的缩放交互（Roam）与页面滚动容易冲突。建议在移动端增加“双指缩放”提示，或进入地图时全屏锁定。
    
2. **图片压缩**：用户上传原图可能导致 localStorage 爆满或加载卡顿。引入 browser-image-compression 库，在上传/保存前压缩图片。
    
3. **性能优化**：地图组件目前的重绘逻辑可以优化，避免每次 props 变动都全量 setOption。
    

### Phase 2: 社交与云端 (Mid-term)

1. **用户系统**：接入微信登录或手机号登录。
    
2. **云相册**：实现上述的后端对接，将数据迁移至云端。
    
3. **千人绘中华**：开发一个“广场”功能，可以看到所有用户点亮了哪些区域（匿名热力图），营造“天涯共此时”的社区感。
    

### Phase 3: 智能化深耕 (Long-term)

1. **RAG (检索增强生成)**：随着用户记录增多，AI“伴”可以利用向量数据库（Vector DB）检索用户过去的记录。
    
    - 例子：“上次我们在杭州遇雨，这次来苏州又是烟雨蒙蒙，你似乎和江南的雨很有缘分呢。”
        
2. **自动生成游记**：基于用户零散回答的几个问题（地点、天气、心情），利用大模型自动润色生成一篇文采斐然的古风长文。
    
3. **实物周边**：对接打印服务，将用户的“画卷”通过热敏打印机打印成真实的纸质长条，作为文创产品。

目前的版本已经具备了非常独特的艺术气质。**“克制”**是后续开发的核心关键词。不要堆砌功能，保持界面的留白，保持交互的慢节奏，让用户在快节奏的数字生活中，感受到片刻的东方宁静。
